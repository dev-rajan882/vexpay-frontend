Gateway Integration Manual

Designed for Developers & AI Prompt Engineering

VexPay uses dynamic paise slotting (0.01 – 0.30) to match incoming bank payment emails with orders in real-time. Follow the contracts below to connect your checkout.

1. Authentication & Base URL

All merchant API calls require your application's API Key. The Gateway auto-detects its current host URL:

Header Required: x-vex-api-key: YOUR_APP_API_KEY

2. Create Payment Order (Website Backend → Gateway)

Call this endpoint whenever a user clicks "Add Funds" or "Pay Now" on your website.

POST /api/v1/orders

// Example Node.js Backend Route
const response = await fetch(`${GATEWAY_URL}/api/v1/orders`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-vex-api-key": process.env.VEX_API_KEY
  },
  body: JSON.stringify({
    amount: 100,                     // Requested base amount
    currency: "INR",
    app_order_id: "ORD_" + Date.now(), // Unique order ID on your site
    customer_id: "USER_101"
  })
});

const data = await response.json();
// data.order.payableAmount -> Exact amount to show user (e.g. 100.04)
// data.order.qrImageUrl    -> Dynamic QR code image
// data.order.upiIntentUrl  -> Mobile UPI app intent link
// data.order.expiresAt     -> Order expiry timestamp (5-minute timer)

3. Webhook Listener (Gateway → Website Backend)

When the customer pays the exact amount, VexPay verifies it via Paytm alerts and dispatches an instant signed POST webhook to your server.

// Express.js Webhook Controller
import express from 'express';
import crypto from 'node:crypto';

const app = express();
const WEBHOOK_SECRET = process.env.VEX_WEBHOOK_SECRET;

app.post('/api/webhook/payment', express.raw({ type: 'application/json' }), (req, res) => {
  const signature = req.headers['x-vex-signature'];
  const rawBody = req.body;

  // 1. Verify HMAC Signature
  const expectedSignature = 'sha256=' + crypto
    .createHmac('sha256', WEBHOOK_SECRET)
    .update(rawBody)
    .digest('hex');

  if (signature !== expectedSignature) {
    return res.status(401).send('Invalid signature');
  }

  const event = JSON.parse(rawBody.toString('utf8'));

  // 2. Handle verified payment
  if (event.type === 'payment.success') {
    const { app_order_id, base_amount, utr, transaction_id } = event.data;

    // A. Check if already processed (Idempotency)
    // B. Credit user's wallet with base_amount (e.g., 100.00, NOT 100.04)
    // C. Mark order as SUCCESS in your database
    console.log(`Payment confirmed for Order: ${app_order_id}, UTR: ${utr}`);
  }

  return res.status(200).send('OK');
});

4. Check Order Status Fallback (Polling API)

Your frontend or checkout UI can poll this endpoint every 3 seconds to auto-redirect users once payment completes.

GET /api/order-status?orderId={orderId}

// Frontend Status Polling
async function pollOrderStatus(orderId) {
  const check = setInterval(async () => {
    const res = await fetch(`${GATEWAY_URL}/api/order-status?orderId=${orderId}`);
    const data = await res.json();

    if (data.status === 'SUCCESS') {
      clearInterval(check);
      alert('Payment Verified! UTR: ' + data.utr);
      window.location.href = '/payment-success';
    } else if (data.status === 'EXPIRED') {
      clearInterval(check);
      alert('Payment window expired. Please initiate again.');
    }
  }, 3000);
}

5. Critical Rules for Developers & AI Agents

  • Credit the Base Amount: Always credit base_amount (₹100) to the user's wallet, never the slotted paise (₹100.04).
  • 5-Minute Lifetime: Orders and slots expire in 5 minutes. Never accept payments after expiration.
  • Raw Body for Signature: Verify the HMAC signature against the raw, unparsed request buffer.
